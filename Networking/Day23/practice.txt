DAY 23 — DNS PRACTICE / LAB
============================

OBJECTIVE:
Practice DNS resolution, connectivity testing, route tracing,
and basic website timing analysis using Linux commands.


--------------------------------------------------
1. INSTALL DNS UTILITIES
--------------------------------------------------

Command:

Install the DNS utilities required to use nslookup.

Installation completed successfully.

--------------------------------------------------
10. TRACE ROUTE — SAARTHIK
--------------------------------------------------

Command:

traceroute saarthik.com

Observed:

The route passed through multiple hops before reaching
the destination.

Some hops showed private IP addresses.

Some hops displayed:

* * *

Observation:
Not every router responds to traceroute probes.

The * * * entries do not automatically mean that the
network is broken.

--------------------------------------------------
12. WEBSITE TIMING — SAARTHIK
--------------------------------------------------

Command:

curl -o /dev/null -s -w \
"DNS: %{time_namelookup}s\nConnect: %{time_connect}s\nTLS: %{time_appconnect}s\nTTFB: %{time_starttransfer}s\nTotal: %{time_total}s\n" \
https://saarthik.com

Observed during one test:

DNS:
approximately 0.014 s

Connect:
approximately 0.222 s

TLS:
approximately 0.459 s

TTFB:
approximately 1.230 s

Total:
approximately 1.449 s


Observation:
DNS lookup itself was very fast.

A significant amount of time was spent establishing
the connection/TLS session and waiting for the server
to begin responding.

14. SAARTHIK — REPEATED TIMING TEST

https://saarthik.com

Repeated several times.

Observed Total times were approximately:

2.61 s
1.64 s
1.61 s
2.15 s

Observation:
The response time varied between requests.

This shows that website performance can fluctuate
between requests.


--------------------------------------------------
15. WHAT WE LEARNED FROM THE INVESTIGATION
--------------------------------------------------

DNS:
Domain names are resolved into IP addresses.

nslookup:
Used to investigate DNS resolution.

ping:
Used to test reachability and measure round-trip latency.

traceroute:
Shows the network path toward a destination.

curl timing:
Helps break website connection time into stages such as:

DNS lookup
Connection
TLS
TTFB
Total response time


--------------------------------------------------
FINAL LAB CONCLUSION
--------------------------------------------------

Investigated several real websites using Linux
networking tools.

Observed that:

- One domain can have multiple IP addresses.
- DNS resolution can be successful even when other
  network problems exist.
- Ping latency can vary between websites.
- Packet loss can occur on a route.
- Traceroute can reveal the path toward a destination.
- DNS lookup time is only one part of website loading time.
- TTFB and total response time are useful indicators
  when investigating website performance.
